## 1. ID·재생길이로 권리나 검수를 판단하지 않는 공통 코드

`client/src/lib/publicationPolicy.ts`에 공개 승인, 품질 검수, 공개 프리뷰 권리, 루프 검수, 리사이즈, 라이선스 협의 조건을 나누었다. 승인 표시를 하려면 작품 ID·콘텐츠 버전·검수 범위·근거 ID·검토자 ID·검토일·만료일이 해당 판단과 맞아야 한다. 미래 검토일, 만료, 다른 작품/버전/범위, 승인 상태만 있고 근거가 없는 입력은 확인 필요로 처리한다.

Open/Originals라는 분류, ID 문자값, 영상 길이, 카페·힐링 같은 태그는 승인 근거가 아니다. 공개 허용과 상업 사용 계약도 별개다. 배지와 필터는 동일한 판단값을 사용하도록 함수가 준비되어 있다. 공개 반환값에는 검토자·근거 ID·계약 원문을 포함하지 않는다.

**한계:** 이 코드는 기록 형식·범위·기간의 일치를 검사한다. 근거 문서의 진위, 검토자의 실제 권한, 계약 효력까지 검증하는 인증/법률 시스템은 아니다. 서버에서 권한 통제된 기록을 공급해야 한다. 브라우저 임의 입력을 신뢰해 공개 승인하면 안 된다.

## 2. 실제 330개 입력을 검토 대기 목록으로 점검

`audit-publication-policy.cjs`를 실제 카탈로그 감사 결과에 실행했다. 정규화된 318개와 썸네일이 없어 제외됐던 12개를 모두 포함해 330개를 점검했다. 공급된 승인 근거 기록은 0개여서 자동 승인/자동 공개는 0개다. **이는 권리가 없다는 판정이 아니라, 이번 입력에서 확인 근거를 확보하지 못했다는 뜻**이다.

작품별 메타데이터 지문, 누락 원인, 필요한 검수 항목과 다음 행동을 JSON으로 기록했다. 이 지문은 `catalog-meta-v1:*`이며 영상 실제 바이트의 지문이 아니다. 미디어가 바뀌었는지는 별도 확인이 필요하다. 검사 결과를 이용해 기존 공개 목록을 일괄 삭제하거나 277개 Creator 후보를 새로 공개하지 않았다.

## 3. 배포 원본 재추적과 로컬 수집 도구

두 저장소의 현재 원격 브랜치 6개에서 배포 전용 파일명 10개를 대조했고 일치 경로가 없었다. 가져온 이력에서도 BuyerProofSummary.tsx, PreviewPlayer.tsx, PrivacyPage.tsx라는 세 경로 표지의 기록을 찾지 못했다. 이름을 바꾼 이력이나 미푸시/미커밋 원본까지 없다고 단정하지 않는다.

`/_src`와 `/_logs`는 Vercel의 해당 배포 source/logs 화면으로 307 이동한다. Git 소스 자체를 공개하는 응답이 아니다. build-info와 두 소스맵 주소는 404 HTML을 반환했다. Vercel 연결 도구는 팀 목록/프로젝트 소스 접근을 확보하지 못했다. 따라서 정확한 배포 Git SHA는 여전히 미확정이다.

`scripts/discover-lumos-source.py`는 실제 개발 PC에서 지정한 작업폴더만 읽는다. 파일명 표지, Git SHA/branch/dirty, `.vercel/project.json`의 projectId/orgId, 저장된 JS/CSS 바이트 지문을 확인한다. 환경변수/비밀번호/브라우저 정보를 수집하지 않는다. 전체 드라이브·심볼릭 링크·node_modules는 피하고, 기존 파일을 덮어쓰지 않는다. 선택 소스 ZIP은 client/src, server, shared, patches와 필수 진입/설정 파일만 포함하며, 폰트·환경파일은 제외한다. 잠재 자격증명 발견 시 수집을 중단한다. 탐지기가 모든 비밀정보를 보증하는 것은 아니므로 공유 전 검토가 필요하다.

**이 도구를 사용자 PC에서 실행한 것은 아니다.** 후보 탐색·권한 오류·심볼릭 링크·누락/비밀정보·수집 파일 보존 등 21개 임시 파일 테스트까지 실행했다.

## 4. 현재 배포와 검토본의 브라우저 재검증

각각 15개 경로 × 1440px/390px, 합계 60개 페이지 로드를 검사했다. 페이지 검사 오류 0건, 런타임 페이지 오류 0건, 문서 전체 가로 넘침 0건이었다. 이는 개별 버튼이 모두 보인다는 뜻이 아니다. 실제 배포의 모바일 상세 주 문의 버튼은 화면 밖에 있어 클릭이 실패했다.

| 항목 | 현재 배포 | 검토본 |
|---|---|---|
| 선택 카드 제목=상세 제목 | 불일치 | 일치 |
| 선택 작품명 문의 자동 입력 | 전달 안 됨 | 전달됨 |
| 문의창 키보드 포커스 유지 | 이탈 | 유지 |
| 없는 작품 주소로 SPA 이동 | 직전 작품 남음 | 없는 작품 안내 |
| 모바일 상세 주 문의 버튼 | 화면 밖 클릭 실패 | 클릭 가능 |
| 문의 전송 실패 시 입력 보존 | 실제 전송 미검사 | 모의 503 응답에서 보존 |

**직접 교체하면 안 되는 추가 근거:** Creator Works 검색 초기화 후 화면 카드가 배포본은 4개, 검토본은 277개였다. 이는 전체 작품 수나 공개 권리 수가 아니라 해당 화면 상태의 카드 수다. 데이터 통합 패치를 그대로 배포하면 노출 범위까지 달라지므로, 기존 공개 범위와 원본 UI를 보존한 선택적 이식이 필요하다.

두 환경의 대표 카드가 서로 달라 제목 비교는 각 환경 내부의 카드→상세 일치 검사다. 실제 문의 이메일은 발송하지 않았다. 검토본의 모의 전송만 별도로 가로채 처리했다. 기존 검토본 대비 JS/CSS 번들 지문은 동일했다. 이번 정책 모듈이 아직 실제 UI에 연결되지 않았다는 점과 일관된다.

## 5. 미디어 상태와 실행하지 못한 부분

깨끗한 Git 소스 기준 로컬 참조는 386개, 누락은 324개다. 현재 배포에 대한 HEAD 검사에서는 381개가 미디어 응답, 5개는 실패였다. **HEAD 성공은 전체 파일 재생 성공·납품 규격·루프 연결·이용 권리 검증이 아니다.** 기존 267개 이미지 백업은 이전 산출물로 보존되어 있다.

추가 영상 다운로드·전체 디코딩 도구를 준비했으나, 해당 파일의 GitHub 등록이 도구에서 안전 상태를 판단하지 못해 차단되었다. 동일 작업을 다른 방식으로 우회하지 않았고, 실제 영상 다운로드/전수 디코딩은 실행하지 않았다. 따라서 52개 영상의 실제 해상도·FPS·전체 디코딩 완료나 새 영상 백업 완료를 주장하지 않는다. 그 시험용 파일은 이번 검토 커밋과 배포 검증 범위에 포함하지 않았다.

## 다음 작업의 단일 시작점

**실제 사이트를 개발했던 PC의 원본 작업폴더를 확보한다.** 동봉된 `실제원본확보_실행지시.md`를 그 PC의 Codex/Claude Code에 전달하면 지정 폴더 탐색 → 후보/배포 연결 확인 → 비밀정보를 뺀 선택 소스 수집 → 원본 보존 이식 순서로 진행할 수 있다. 원본이 확인되기 전에는 배포본을 구버전 검토 소스로 교체하지 않는다.

원본 확보 후에는 배지·필터의 근거 없는 판단을 공통 정책으로 교체하고, 최신 구매자 안내/플레이어/개인정보/약관/포털을 유지한 상태에서 문의·카탈로그 수정만 옮긴다. 실제 공개 승인 기록과 미디어 저장/재생 검증은 그 후속 단계에서도 필요하다.
