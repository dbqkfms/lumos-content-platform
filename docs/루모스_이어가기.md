## 가장 중요한 다음 작업

**실제 배포 원본을 찾고 필요한 수정만 이식한다.** 공개 배포에는 현재 Git 기준에 없는 BuyerProofSummary, PreviewPlayer, WebpImage, PrivacyPage, TermsPage, PressPage 등의 후속 구현이 있다. 기존 공개 사이트를 검토 브랜치로 그대로 교체하면 기능이 줄어든다. 배포의 Git SHA는 미확정이다.

Vercel 연결 list_teams는 빈 목록, 보호 URL 도구는 403이다. 저장소 deploy/.vercel/project.json은 NUL 파일이다. 그러나 기존 GitHub Actions 검증 실행기에서 공개 사이트 읽기와 브라우저 검사는 가능했다. 같은 실패 접근을 반복하거나 공개 사이트를 못 봤다고 되돌아가지 않는다. 검토 브랜치 전용 기존 workflow를 활용한다.

배포 코드의 '독점 가능/비독점'은 ID 문자값 합 %3, '반복재생 안정'은 8초 초과로 만들어진다. 검수/리사이즈 필터도 ID 산술이다. 이것을 먼저 실제 기록 기반으로 바꿔야 한다. accessTier는 컬렉션 분류일 뿐 권리 승인 값이 아니다.

전체 입력 330개 중 썸네일 없는 12개 제외, 유효318개. 현재 검토 분류는 Originals41 / Creator277 / Open0이다. 기존 배포 Creator4개와 차이가 크다. 공개 허용·검수 상태를 확인하기 전 277개를 자동 공개하거나 Open12개를 임의로 채우지 않는다.

## 유지 조건

Open/Free, LUMOS Originals, Creator Works, STANDARD/LOCAL, public+작가/관리자 포털을 유지한다. 단순 영업사이트로 축소하지 않는다. 실제 배포에 이미 있는 추가 필드와 화면을 없애지 않는다. 누락 영상에 무관한 영상을 넣지 않는다. 원본 미커밋 변경·비밀정보를 보존하고 토큰/환경변수를 공유하지 않는다.

main 병합·운영 alias/배포·실제 문의 발송·라이선스 확정은 별도 승인 전 금지한다. 임시 브라우저의 모의 전송만 허용한다. GitHub workflow는 contents:read, 자격증명 보존 없음, 별도 운영 배포 없음이다.
