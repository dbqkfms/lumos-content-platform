세 콘텐츠 축, STANDARD/LOCAL, public+portal 통합을 보존한다. 앞선 단순 영업사이트 축소, Sign in/포털 제거 제안은 채택하지 않는다. 포털은 데모와 실제 인증/권한 적용 상태를 구분해서 개선한다.

## 반드시 알아야 할 동작 변화

`accessTier: "open"`은 담당자가 명시한 작품만 Open에 노출한다. 미기재 외부 데이터는 provenance상 Creator로 분류한다. 이는 상업 사용 허락이나 공개 권리의 검증을 뜻하지 않는다. 기존의 추정 Open 데이터에 명시값이 없다면 Open이 비어 있을 수 있다. **배포 전 공개 허용 작품을 확인하고 메타데이터를 채워야 한다. 임의로 12개를 골라 허용하지 않는다.**

worldType/line도 없고 기존 standard-/local- ID도 아닌 자료는 unclassified에 남긴다. 전부 LOCAL로 넣어 수치를 맞추지 않는다. 목록과 상세의 통합으로 기존 managed 데이터가 목록에 추가되거나 ID 기반 중복 처리로 개수가 달라질 수 있으므로 전체 데이터 ID 비교가 필수다.

displayType 누락 시 기존 Horizontal 호환 기본값은 남아 있다. 규격 검증 완료를 뜻하지 않는다. 해상도/FPS/실제 반복구간/원본 납품 권한 검증도 다음 단계다.

## 다음 실행 순서

### 1. 배포 원본 확정 — 운영 변경의 필수 조건

로그인된 Vercel 환경 또는 로컬 `.vercel/project.json`에서 실제 projectId/orgId를 확인한다. 토큰·키를 채팅이나 보고서에 복사하지 않는다. 해당 alias가 가리키는 deployment ID, gitSource/meta의 repo/branch/SHA, rootDirectory, buildCommand, outputDirectory, 실제 빌드 기록을 확인한다.

Git 연동 정보가 없으면 로컬 미커밋 파일/업로드 파일을 별도 보존하고 소스 지문·실제 JS/CSS 지문·HTML·에셋 매니페스트로 비교한다. 도메인 이름/페이지 제목/이전 대화만으로 확정하지 않는다. 소스가 다른 경우 이번 패치를 자동 적용하지 말고 필요한 수정만 이식한다.

### 2. 전체 카탈로그 검증

배포 기준 원본에서 작품 ID, 제목, worldType, accessTier, thumbnail, videoSrc/embedUrl, sourceType 목록을 추출해 수정 전후 대조한다. 한국어 제목/설명/태그 보존, STANDARD의 LOCAL 이동 0건, 미지정 Open 0건, 동일 ID 카드와 상세 메타 일치를 확인한다. 중복 ID, 동일 미디어 다른 ID, unclassified를 별도 보고한다.

### 3. 미디어 누락과 재현성

`pnpm audit:media`로 `dist/audits/media-report.json`을 만든다. client/public/videos, generated-thumbnails 등이 Git에서 제외된 점을 반영해 원본 자산을 승인된 CDN/저장소/다운로드 매니페스트로 연결한다. 없는 영상을 무관한 대체 영상으로 채워 통과시키지 않는다. UI 200응답만 보지 말고 MIME·실제 디코딩·Vimeo 접근권한을 확인한다.

### 4. 빌드와 브라우저 검증

깨끗한 별도 작업 트리에서 다음을 실행한다:

```sh
pnpm install --frozen-lockfile
pnpm test:round1
pnpm check
pnpm audit:media
pnpm build
```

Vercel buildCommand가 pnpm build를 우회하면 write-build-info 단계도 실행되도록 설정을 검토한다. 설정은 승인 없이 변경하지 않는다. 새 프리뷰에서 `/build-info.json`이 실제 JSON인지 확인한다. SPA fallback HTML의 200 응답은 성공이 아니다.

/, /open, /originals, /creator-works, /standard, /local, 작품 상세, /solutions, /platform, /contact, /login 및 두 포털을 확인한다. 390px/1440px에서 한글 줄바꿈, 검색/필터, 카드→상세, Vimeo/mp4, 키보드 탐색, 문의 모달을 검사한다. 실제 문의를 보내려면 수신 대상과 테스트 전송 승인을 확인한다.

### 5. 이후 UI·카피 개선

실제 배포 화면에 남은 문제만 다룬다. route-specific head/OG, 구매자용 문의 이후 결과 안내, CTA 문구, hover/focus 일관성, 제작자 안내를 정리한다. 홈/Platform/Solutions를 같은 설명으로 중복하지 않는다. 검수·AI·납품·응답시간을 미검증 완료 기능처럼 표현하지 않는다.
