공개 배포에는 후속 구매자 안내, 작가/법적 안내 페이지, 추가 필터와 배지, 포털 연결, 확장된 문의 양식이 있다. 검토 브랜치의 예전 페이지 전체로 이를 교체하지 않는다. 컴파일 결과에 없는 원본 편집 파일을 복구한 것처럼 말하지 않는다.

콘텐츠 관리자 JSON은 소스 279개와 배포 279개의 ID가 모두 같다. 278개 레코드는 동일하고 1개만 변경됐다. `lumos-91336e22`의 title/titleKo가 소스의 `신수의 강림`에서 배포의 `test`로 바뀌었다. JS만 비교해서는 이 변경을 잡지 못하므로 새 빌드 정보에 데이터 JSON 지문도 추가했다.

## 가장 중요한 실제 배포 결함: 권리·검수 표시가 데이터가 아님

배포 JS에서 다음 로직을 직접 확인했다. 원문 지문이 위 표에 고정돼 있고 별도 증거 JSON에 코드 구간을 저장했다.

- Creator/Open의 독점 가능·비독점·협의중은 작품 ID 문자값 합을 3으로 나눈 나머지로 정해진다.
- `권리확인`과 `리사이즈 가능` 배지가 조건 없이 추가되는 경로가 있다.
- `반복재생 안정`은 실제 루프 검수 대신 길이에서 숫자를 추출해 8초를 넘는지로 표시된다.
- 검수/리사이즈 필터에도 ID 산술을 사용한다.

예시 원문: `(n.id||"").split("").reduce((m,g)=>m+g.charCodeAt(0),0)%3`.

따라서 이 배지와 필터를 실제 계약·권리·검수 사실로 취급할 수 없다. **실제 배포 원본에 가장 먼저 이식해야 할 수정**이다. `reviewStatus`, `rightsReviewStatus`, `licenseMode`, `loopReviewStatus`, `resizeSupport`를 명시 기록으로 나누고, 근거가 없으면 확인 필요/조건 협의로 표시한다. 컬렉션 분류값 `accessTier`만으로 사용 허락까지 확정하지 않는다.

현재 원본을 확보하지 못했으므로 배포 파일을 몰래 수정하지 않았다. 검토 브랜치에서는 순서·길이·키워드 기반 Open 선정과 자동 보충을 제거했지만, 이것이 위 후속 배포 UI까지 수정됐다는 뜻은 아니다.

## 실제 데이터 감사

정적 작품은 STANDARD 17개 + LOCAL 24개, managed 10개, 콘텐츠 관리자 279개로 입력 총 330개다. 12개는 썸네일이 없어 정상화 단계에서 제외된다. 318개 고유 ID의 원문 메타와 영상 URL이 보존되며 중복 ID/동일 미디어 키는 검사 범위에서 없었다.

정상화 결과는 Originals 41개 / Creator 277개 / Open 0개다. Open으로 명시된 항목이 없기 때문이다. 담당자 확인 없이 Open을 다시 12개로 채우지 않는다. 기존 배포 Creator 화면은 4개만 표시했으므로 **277개를 바로 공개하라는 뜻도 아니다.** 배포 원본에서 공개 대상과 권리 검토를 먼저 확정해야 한다.

원본 worldType이 STANDARD인 콘텐츠 관리자 유효 자료 253개를 이전 ID 기반 규칙은 LOCAL로 분류할 수 있었다. 명시된 worldType을 따르도록 고쳤다. 현재 STANDARD/LOCAL 페이지는 전체 worldType 필터이므로 Originals 하위 전용인지 전체 스타일 분류인지는 사업 정의와 함께 고정할 필요가 있다.

외부 입력 289개(10+279)의 저장된 메타데이터 중 263개가 FHD보다 낮은 치수로 기재돼 있고 12개는 해상도 확인이 필요했다. 이는 **기재된 값**에 대한 감사이지, 실제 납품 원본의 해상도 측정이 아니다. 첫 항목 `디지털 기록`은 설명상 작업관리 앱 기능 시연이어서 미디어아트 컬렉션에 적합한지 별도 검토 대상으로 남겼다. 작품을 임의 삭제하거나 고해상도라고 꾸미지 않았다.

## 미디어 보존과 재현성

386개 리터럴 참조에는 현재 화면에서 쓰지 않는 mockData도 포함된다. 공개 서버에서 실패한 5개 경로는 `local-cafe-bloom.jpg`, `local-rain.jpg`, `standard-cosmic.jpg`, `standard-light.jpg`, `standard-sansu.jpg`이며 mockData 참조다. 이를 전부 활성 공개 화면의 이미지 오류라고 단정하지 않는다.

별도로 실제 Solutions 화면의 `/mockups/v3/standard-noe.webp` 404는 확인했다. 이는 기준 소스의 386개 리터럴 목록과 다른 후속 UI 자산이다.

Git에 없지만 공개 서버에 있는 이미지 267개를 동일 URL의 원본 바이트로 백업했다. SHA-256 대조와 Pillow 전체 디코딩 267개가 통과했다. 사이트나 Git 저장소에 이미지 자체를 다시 업로드하지 않았고, 운영 가능한 영구 스토리지 결정도 하지 않았다. 공개 alias는 변경 가능한 복구 출처이며 영구 CDN 보장이 아니다. 영상은 이번 백업에 포함하지 않았다.

## 이후 실행 지점과 완료 조건

새 설계부터 다시 시작하지 말고 실제 배포 원본 폴더 또는 올바른 Vercel 프로젝트 권한부터 확보한다. `BuyerProofSummary.tsx`, `PreviewPlayer.tsx`, `PrivacyPage.tsx`가 있는 로컬 LUMOS/Antigravity 작업폴더가 유력한 탐색 표지다. 토큰·비밀 파일은 제출하지 않는다.

실제 원본에 배지의 명시 데이터화 → 검증된 카탈로그/문의/상세 수정 이식 → 모바일 정보 레이아웃 → 올바른 미디어 경로·임베드 → 직접 URL rewrite → 전체 회귀 순으로 연결한다. 기존 후속 문의 필드/동의 절차·개인정보 페이지를 검토본의 예전 구조로 되돌리지 않는다.

58개 테스트, 전체 타입검사·빌드, 실제 카탈로그 전후 비교, 필요한 자산 재현성·재생, 화면 전후 보존이 모두 충족되어야 한다. 코드 빌드 통과만으로 상업 운영 준비 완료를 선언하지 않는다. main/운영 반영은 별도 승인 후다. 롤백은 이번 작업 커밋만 revert하며 hard reset/강제푸시/기존 작업 삭제는 하지 않는다.
